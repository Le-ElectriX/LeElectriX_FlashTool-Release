Important Safety Information#

Warning: Firmware flashing, controller resets, self-learning, and motor torque/speed control may cause the equipment to stop, restart, or move mechanically. Before operation, you must confirm that the controller is in a safe bench environment, no one is in the shaft or load area, the emergency stop is available, and the power supply and CAN connection are stable. Only personnel who are authorized and familiar with the equipment safety standards may perform these operations.
Note: The interface screenshots in this manual show an unconnected device or an empty-data state. They illustrate button locations and do not indicate that writing, flashing, or motion control has been performed on customer equipment.

Quick-Start Workflow#

  1. Download and install .NET 8 SDK x64 and the CAN adapter driver.
  2. Install and start LeElectriX FlashTool.
  3. Load a valid license.
  4. Scan for CAN devices, select the channel and bit rate, and connect.
  5. Open the Flashing, MCU Default Parameters, MCU Calibration, TRACE, or Tools page as appropriate for the operation.
  6. If a problem occurs, record the time and collect the logs by opening the log directory from the Settings page.

2.4 Install the VC++ Runtime if the ZLG Driver Library Cannot Load#

Some Windows computers lack the VC++ runtime required by the ZLG driver library. In this case, LeElectriX FlashTool may still fail to detect the device even after its driver has been installed, or an error may occur when the ZLG driver library is loaded.

  • ZLG issue description:

https://manual.zlg.cn/web/#/152?page_id=5332

  • VC++ runtime package provided by ZLG:

https://manual.zlg.cn/Public/Uploads/2020-06-05/5ed995c271414.zip

Prerequisite: Use a Windows account with administrator privileges, and close LeElectriX FlashTool and any other application using the CAN adapter.

Procedure:

  1. Download the VC++ runtime archive above.
  2. Extract it to a temporary directory.
  3. Right-click MSVBCRT.AIO.2019.10.19.X86 X64.exe and select Run as administrator.
  4. Follow the installer prompts to install the Microsoft Visual C++ 2015–2019 x86/x64 runtime.
  5. Restart Windows after installation.
  6. Reconnect the ZLG adapter and scan for devices in LeElectriX FlashTool.

Expected result: The ZLG driver library loads normally and the application detects the correctly connected adapter.

Troubleshooting:

  • If the adapter still cannot be detected, confirm in Windows Device Manager that it has no yellow warning symbol.
  • Reinstall the ZLG driver matching the device model, and install the VC++ runtime again.
  • Do not obtain DLL files of unknown origin from third-party download sites and manually copy them to a system directory.

5. Scan and Connect a CAN Channel#

5.1 Pre-connection Checks#

  • The CAN adapter driver is installed.
  • The CAN adapter is connected to the computer and target device.
  • CAN_H, CAN_L, ground, and termination resistance meet the system requirements.
  • The target controller is powered normally.
  • No other application has exclusive control of the CAN adapter.

5.2 Scan for a Device and Connect#

Procedure:

  1. Open the Status page.
  2. Click Rescan the CAN device in the center.
  3. Select the CAN device in the first drop-down list.
  4. Select the physical channel in the second drop-down list, such as Channel_1.
  5. Select the bit rate used by the target system in the third drop-down list.
  6. Click Connect/Disconnect on the left to establish the connection.
  7. Observe the CAN status indicator in the upper-right corner.

Expected result:

  • The page displays the device name, manufacturer, and version information.
  • The CAN status indicator changes from disconnected to connected.
  • Subsequent modules can transmit and receive frames normally.

Troubleshooting:

  • No device in the drop-down list: reconnect the adapter, check the driver, and close any software that may be using the device.
  • A device is present but no channel is available: confirm that the correct model is selected and rescan if necessary.
  • Connection failure: check whether the channel is already in use, the bit rate is correct, and the target device is powered.
  • Disconnect the current connection before changing the CAN device or channel.

5.3 Scan the Bit Rate Automatically#

Prerequisite: The CAN adapter and target controller are connected correctly, and periodic frames are continuously present on the target bus.

Procedure:

  1. Ensure that frames are continuously present on the target bus.
  2. Click Auto scan the bit rate on the right.
  3. Wait for the application to test the supported bit rates in sequence.
  4. After a successful scan, confirm the displayed bit rate before establishing the connection.

Expected result: The bit-rate drop-down list displays the detected bit rate, and that bit rate can be used to establish a CAN connection and receive frames.

Troubleshooting:

  • If no frames are present on the bus, the application cannot determine the correct bit rate; confirm it from the device documentation and select it manually.
  • If scanning always fails, check the controller power supply, CAN_H/CAN_L wiring, termination resistance, and adapter channel.
Note: Automatic scanning cannot determine the correct bit rate when no frames are present on the bus. In this case, confirm the bit rate from the device documentation and select it manually.

6. Use the Flashing Module#

6.1 Pre-flashing Checks#

  • The correct CAN device and channel have been connected successfully.
  • The target controller model, firmware file, and flashing procedure match one another.
  • The supply voltage is stable and the communication lines are reliable.
  • Other operations that may affect the controller have been stopped.
  • A recovery procedure for a power loss or flashing failure has been confirmed.

6.2 Load a HEX File#

Procedure:

  1. Open the Flashing page.
  2. Click the folder button to select a .hex file.
  3. Check the file name and last-modified date displayed on the page.
  4. To read the file again, click Refresh.
  5. To locate the file, click Open File Location.

Expected result: The file information area displays a valid firmware file and the flashing button is available.

Troubleshooting:

  • Invalid file: confirm that the file is not damaged and uses a supported HEX format.
  • File does not match the controller: stop the operation and check with the firmware provider.
  • Do not determine firmware applicability from the file name alone.

6.3 Start Flashing#

Prerequisite: The checks in Section 6.1 are complete, the HEX file information is correct, and the target controller has not started erasing or transferring data.

Procedure:

  1. Confirm the target controller and firmware version again.
  2. Click Start downloading/flashing.
  3. Read the confirmation prompt and continue after confirming that the information is correct.
  4. Observe the progress bar at the bottom and the log list in the center.
  5. Wait until the application explicitly reports that flashing succeeded.

Expected result: Progress reaches 100%, a success message appears in the log, and the page displays the total elapsed time.

Warning: During flashing, you must not close the application, disconnect CAN, unplug USB, or cut power to the target controller. Do not operate other modules unless the application explicitly instructs you to do so.

6.4 Unable to Enter the Bootloader Session#

Prerequisite: The log explicitly shows that the application is still waiting to enter the Bootloader and has not started erasing or transferring data.

Warning: Power may be cycled as described in this section only when the prerequisite above is met. Once the log shows that erasing or data transfer has started, cutting controller power, disconnecting CAN, or unplugging USB is strictly prohibited.

Procedure:

  1. Keep the current flashing request running; do not click Stop immediately.
  2. Cut controller power in accordance with the target-device safety standards.
  3. Wait at least 5 seconds.
  4. Power the controller on again.
  5. Observe the log to determine whether the flashing session is entered successfully and transfer begins.
  6. If it still fails, stop the operation and check the CAN bit rate, Bootloader configuration, power supply, and firmware compatibility.

Expected result: After being powered on again, the target controller enters the Bootloader and the log starts showing erasing or data-transfer progress.

Troubleshooting:

  • Still waiting after power is restored: stop the flashing request and check the bit rate, wiring, Bootloader configuration, and firmware compatibility.
  • Communication error after erasing or transfer has started: do not perform the power-cycle procedure in this section again; retain the logs and contact technical support.

7. Use the MCU Default Parameters Module#

Prerequisites:

  • CAN is connected.
  • The target controller matches the current application version.
  • The target device is in a state that permits reading or control.

7.1 Automatic Handshake, Parameter Reading, and Parameter Refresh#

Procedure:

  1. Click the MCU icon on the left to open the MCU Default Parameters page.
  2. After the page opens, the application automatically initiates the MCU communication handshake; there is no need to click a handshake button manually.
  3. Observe the MCU connection-status icon in the upper-right corner and continue only after confirming that the handshake succeeded.
  4. Wait for the page to read information such as version, hardware, faults, direction, and operating status automatically.
  5. To read the values again, click Update parameter values at the top.

Expected result: The MCU connection status is normal, parameter values are displayed, and the parameter update time changes after a manual refresh.

Troubleshooting:

  • Handshake status remains abnormal: check the CAN connection, bit rate, and controller power supply; leave this page and open it again to reinitiate the handshake.
  • Page remains empty: return to the Status page, reconnect CAN, and then open this page again.
  • Parameter meaning does not match the device: stop writing and verify the controller model, firmware version, and application version.

7.2 Save Parameter and Code Files#

Prerequisite: The MCU handshake has succeeded and the page has read the current parameters.

The top toolbar provides three types of file operations:

Save Parameters to Your Computer#

Procedure:

  1. Click Update parameter values and confirm that the page has obtained the required parameters.
  2. Click Save parameters to your computer.
  3. Select the save location and file name.
  4. Save the file as a TXT parameter file.

Expected result: A TXT file that can be used for backup or subsequent downloading is created at the target location.

Convert a Parameter File to a Code File#

Procedure:

  1. Click Convert a Parameter File to a Code File.
  2. Select the previously saved TXT parameter file.
  3. Select the location for saving the C file.
  4. Wait for the application to report a successful conversion.

Expected result: A C code file is created at the target location.

Save Current Parameters as a Code File#

Procedure:

  1. Click Update parameter values and confirm that the current page has read the required parameters.
  2. Click Save to code file.
  3. Select the location for saving the C file.
  4. Wait for the application to report a successful save.

Expected result: A C code file based on the current parameter values is created at the target location.

Troubleshooting:

  • No file is created after file selection is canceled; the corresponding operation can be performed again.
  • If conversion or saving fails, confirm that the source TXT file can be read, the target directory is writable, and the target file is not in use by another application.
  • If the parameters are incomplete or their source is unknown, do not use the generated file for an official controller configuration.

7.3 Control Operations#

Warning: The following operations may reset the controller or rotate the motor. Before performing them, you must clear the shaft and load area, confirm that the mechanical system permits motion, and ensure that emergency-stop and power-disconnection means are immediately available. The Stop control sends only a software stop command and cannot replace an emergency-stop device or physical power disconnection.

Prerequisites:

  • The automatic MCU handshake has succeeded and communication status is normal.
  • The operator has obtained control authorization and understands the target-device safety standards.
  • The mechanical system permits commissioning, no one is in the shaft or load area, and the emergency-stop device is available.
  • The first run should begin with a small, approved safe setpoint.
  • For a high-voltage system, parameter-file loading, CAN connection, and communication checks should first be completed with low-voltage power. High voltage may be connected in accordance with the equipment safety standards only after the mechanical safety conditions are confirmed.
  • After the operation, control should first be stopped, the target values set to zero, and the equipment returned to a safe state. Then disconnect high voltage before low voltage in accordance with the equipment safety standards.

Debugging Enable#

Procedure:

  1. Confirm that the controller is in a state that permits commissioning.
  2. Click Debugging enable; the application opens a confirmation dialog.
  3. Check the library version, application version, rated voltage, and current fault information; continue after confirming that they are correct.
  4. Observe the controller status and fault information.

Expected result: The controller enters a state that permits commissioning and no new fault appears on the page.

Start Position Self-Learning#

Warning: The motor may rotate automatically during self-learning. Self-learning must be performed under no-load conditions, with confirmation that the mechanical braking system is applying no braking force. For a complete vehicle, the drive wheels should be raised securely and kept suspended. On a test bench, the motor should be reliably decoupled from the mechanical load. Starting self-learning is prohibited if the no-load conditions are not met.

Prerequisite: The motor, encoder, and controller models match; the drive wheels or shaft can rotate freely; no person, tool, or loose object is in the rotation area; and the emergency stop and high-voltage power-disconnection means are immediately available.

Procedure:

  1. With low-voltage power connected, complete the CAN connection and automatic MCU handshake; read and record the direction and initial-angle value a1 before self-learning.
  2. Confirm again that the motor is under no load and the drive wheels or shaft can rotate freely.
  3. Connect high voltage in accordance with the equipment safety standards, and confirm that the controller has no fault that affects self-learning.
  4. Click Start position self-learning; the application opens the Confirm Self-Learning dialog.
  5. Read and confirm the prompt, then wait for self-learning to finish completely. Continuously observe speed, current, vibration, sound, and fault status during the process.
  6. Click Update parameter values, view the self-learning status and static self-learning results, and record the post-learning initial-angle value a2.
  7. Save the parameters and operation records from before and after self-learning.
  8. After self-learning is complete, power down, wait 10 seconds, and power on again. Repeat the self-learning operation above and, after updating the parameters, record the initial-angle value a3. Self-learning is completed successfully if |a2-a3| < 1°.

Expected result: The self-learning process finishes normally, the page displays a valid self-learning result, and |a2-a3| < 1°.

Troubleshooting: If self-learning does not finish, the result is invalid, |a2-a3| ≥ 1°, related parameters are not retained, the initial angle after power-up differs from the value at the end of self-learning, or abnormal sound, vibration, current, temperature, or a fault occurs, immediately use the emergency stop or disconnect high voltage in accordance with the equipment standards. Record the status and logs and contact technical support. You must not start self-learning repeatedly in succession.

Software Reset and Reset Parameters#

Software Reset procedure:

  1. Save necessary data and confirm that the device may restart immediately.
  2. Click Software Reset.
  3. Read the confirmation prompt and confirm.
  4. Wait for the controller to come online again.

Reset Parameters procedure:

  1. First back up the current parameters as described in Section 7.2.
  2. Click Reset Parameters.
  3. Read the confirmation prompt and confirm.
  4. Wait for the controller to reset the parameters and come online again.

Expected result: Communication resumes after Software Reset; after Reset Parameters, the parameters return to the default state defined by the target firmware.

Troubleshooting: If the controller does not come online again, check the power supply and CAN connection; do not perform resets repeatedly in succession. After communication resumes, refresh the page and check the faults, version, and key parameters.

Torque Control#

Procedure:

  1. Confirm that the torque-control area is currently in use.
  2. Enter a small, approved safe torque target in the Torque Setpoint input field. Under no-load conditions, even low torque may produce high speed; you must assess the target torque and overspeed risk before setting it.
  3. Press Enter to write the target value.
  4. Confirm that the Torque Setpoint displayed on the page has been updated. If the motor vibrates severely at this point, immediately set the target torque to 0, stop the test, and check whether the initial angle is correct.
  5. Click Forward Rotation or Reverse Rotation as needed.
  6. Continuously observe actual torque, current, speed, and fault status.
  7. At the end, click Stop in the center. Stopping directly at high torque may cause an impact; gradually reduce the torque before stopping.
  8. Click the circular-arrow button beside the setpoint and confirm that the setpoint displayed on the page is 0.

Expected result: The setpoint is written successfully and the controller responds in the selected direction; after Stop is clicked, the software control command stops.

Verify Motor Rotation Direction#

Warning: Rotation-direction verification must be performed under no-load conditions or in the safe test state specified by the project. Before starting speed-loop calibration or another higher-speed test, you must confirm that the actual direction corresponding to the software Forward Rotation command matches the forward direction defined for the vehicle or equipment.

Prerequisite: Position self-learning has been completed; the drive wheels are reliably suspended or the motor is decoupled from the mechanical load; the speed limit specified by the project is set correctly; and the target torque is 0.

Procedure:

  1. Enter a small, approved positive test torque in the Torque Setpoint input field.
  2. Press Enter to write the target value, and check the target value and unit displayed on the page.
  3. Click Forward Rotation and briefly observe the actual rotation direction of the shaft or drive wheels.
  4. If the actual direction matches the forward direction defined for the vehicle or equipment, click Stop, set the target torque to zero, and record the verification result.
  5. If the actual direction does not match, immediately click Stop, set the target torque to zero, and stop subsequent calibration.

Expected result: The actual rotation direction corresponding to the software Forward Rotation command matches the forward direction defined for the vehicle or equipment.

Troubleshooting: If the direction does not match, use the motor-direction correction process approved for the target project. After correcting the direction, you must repeat the complete position self-learning process and verify the direction again. You must not perform speed-loop calibration or increase the test speed before verification passes.

Speed Control#

Procedure:

  1. Confirm that the speed-control area is currently in use.
  2. Enter a small, approved safe speed target in the Speed Setpoint input field.
  3. Press Enter to write the target value.
  4. Confirm that the Speed Setpoint displayed on the page has been updated. If the motor vibrates severely at this point, immediately set the target speed to 0, stop the test, and check whether the initial angle is correct.
  5. Click Forward Rotation or Reverse Rotation as needed.
  6. Continuously observe actual speed, current, temperature, and fault status.
  7. At the end, click Stop in the center.
  8. Click the circular-arrow button beside the setpoint and confirm that the setpoint displayed on the page is 0.

Expected result: The setpoint is written successfully and the controller responds in the selected direction; after Stop is clicked, the software control command stops.

Troubleshooting:

  • If the setpoint does not update after you press Enter, do not start Forward Rotation or Reverse Rotation; first check communication status and the device operating state.
  • If abnormal sound, vibration, current, temperature, or a fault occurs, immediately use the emergency stop or disconnect power in accordance with the equipment standards; do not rely only on Stop in the interface.
  • If an input field cannot be edited, do not attempt to bypass the restriction; contact technical support.
  • If a permission-protected field cannot be edited, contact technical support.

8. Use the MCU Calibration Module#

Prerequisites:

  • A parameter definition file matching the target controller, firmware, and project has been obtained.
  • Before reading or writing, CAN is connected and the automatic MCU handshake has succeeded.
  • Controller power is stable and the controller is in an operating state that permits calibration.
  • The operator has obtained permission to read or modify parameters.
Warning: Calibration involving motor rotation must be performed on a test bench or under complete-vehicle test conditions that comply with the project safety standards. Position self-learning and rotation-direction verification must be completed before speed-loop calibration begins. During the test, ensure that the emergency stop and high-voltage power-disconnection means are immediately available.

8.1 Import a Parameter Definition File#

Example file: F28384_params_MC366WV_General_Pump_FuSa_V0.17.xls

Procedure:

  1. Open the Settings page.
  2. Locate MCU Parameters.
  3. Click the import button to the right of Import a parameter file.
  4. Select an .xls or .xlsx file matching the target controller.
  5. Confirm that the page displays only the correct file name.
  6. Return to the main interface.

Expected result: The Settings page displays the parameter definition file name, and the MCU Calibration page can initialize the parameter list.

Troubleshooting:

  • File-not-found prompt: select the file again, and do not move or delete the original file after importing it.
  • Empty parameter list: confirm that the spreadsheet format and version are compatible with the current application.
  • Parameter meaning does not match: do not perform a write; verify the version with the parameter-file provider.

8.2 Open the Calibration Page#

Procedure:

  1. Click the MCU Extension icon on the left.
  2. Confirm that the page title is MCU Calibration.
  3. Wait for the parameter definition file to load.
  4. After connecting the controller, click Update parameter values.

Calibration parameters are on the left and usually include Name, Description, Actual Value, and Target Value. Process variables are on the right and display read-only actual values.

Expected result: The parameter list is displayed normally, and actual values and process variables can be read after refreshing.

Troubleshooting: If the page is empty or refreshing fails, check the parameter definition file, CAN connection, MCU handshake status, and controller power supply.

8.3 Search and Refresh#

Procedure:

  1. Enter a parameter name or a description keyword in the search box at the top to narrow the parameter list.
  2. Click Update parameter values to read the actual values and process variables in the current filtered results again.
  3. To restore the full list, clear the search box and reselect the parameter groups to display.

Expected result: The list displays only parameters that meet the filter conditions; clearing the filter restores the parameters in the selected groups.

Troubleshooting: If a parameter cannot be found, clear the search box and check the parameter groups. If it is still absent, verify the parameter definition file version.

8.4 Write a Single Parameter#

Note: The current version cannot guarantee automatic upper- and lower-limit validation for every parameter. Before writing, you must check the unit, permitted range, and target value against the approved parameter definition.
Important: Online parameter modifications in this calibration process are not written to the persistent software area and are not retained after controller power-off. After calibration is complete, the final TXT parameter file should be exported before power-off. For details, refer to “Save parameters to your computer” in Section 7.2, Save Parameter and Code Files. If the parameters must take effect permanently, submit the final parameters and test records to technical support, who will generate and flash software that includes the final parameters.

Procedure:

  1. Search for and confirm the target parameter, checking its name and description.
  2. Check the unit, permitted range, and current actual value against the approved parameter definition.
  3. Enter the new value in the Target Value cell.
  4. Press Enter to submit the write.
  5. Click Update parameter values and check whether the actual value matches the target value.

Expected result: No communication error occurs during writing, and the refreshed actual value matches the target value.

Troubleshooting:

  • If a negative value, special format, or numeric range is uncertain, do not attempt to write it; contact technical support to confirm the format and range.
  • Write timeout: check the CAN connection, MCU handshake, and controller status.
  • Actual value does not change: do not write repeatedly in succession; first review the logs and confirm whether the parameter supports online modification.

8.5 Save Current Parameters#

Prerequisite: The parameters to be backed up have been read.

Procedure:

  1. Clear the search box and select all parameter groups.
  2. Click Update parameter values, drag the right-hand scroll-bar thumb to the bottom of the window, and confirm that the current values of all parameters have been read.
  3. Click Save parameters to your computer at the top.
  4. Select the save location and file name, and save the file as a TXT parameter-value file.

Expected result: A TXT parameter-value file is created at the target location. It contains all calibration parameters from the parameter definition file, sorted by parameter number.

Troubleshooting:

  • If the current value of any parameter has not been read, the application refuses to save. Clear the search criteria, select all parameter groups, complete the update, drag the scroll bar to the bottom of the window, and then save again. If the scroll bar has not reached the bottom, parameters below may not yet have been updated.
  • If saving fails, confirm that the target directory is writable and the target file is not in use by another application.

Saving a parameter backup before making batch modifications is recommended; include the device, date, and purpose in the file name.

8.6 Download Parameters to the MCU in Batches#

Prerequisites:

  • A TXT parameter-value file matching the current parameter definition is ready.
  • For a complete download, the search box has been cleared and all parameter groups to be downloaded have been selected.
  • The target controller is correct, its power supply is stable, CAN is connected, and the MCU handshake has succeeded.
  • The current parameters have been backed up as described in Section 8.5, and authorization for batch modification has been obtained.

Procedure:

  1. Confirm the target controller and TXT file version again.
  2. Click Download Parameters to MCU at the top.
  3. Select the TXT parameter-value file and confirm.
  4. After file selection is complete, the application immediately starts writing matching parameters; there is no additional Start button to find.
  5. Wait for the application to display a success or failure result.
  6. The download function downloads only parameters whose parameter numbers match between the currently loaded parameter table and the TXT file.
  7. Click Update parameter values and check all target and key parameters, rather than spot-checking only a small number of items.
Warning: Batch downloading modifies controller parameters continuously. During downloading, you must not cut power, disconnect CAN, or switch to another control operation. Confirm with the software engineer whether the software for this project uses parameters in an EEPROM-backed persistent software area. If the parameters are not persistent, downloaded parameter values return to their default values after a power-off restart.

Expected result: The application reports a successful write, and all refreshed target parameters match the approved TXT file.

Troubleshooting:

  • Items in the TXT file that are absent from the current parameter definition, filtered results, or selected groups may be skipped without a separate prompt. You must confirm the actual write scope by refreshing and checking each item.
  • Some parameters fail: save the prompt information and logs; do not blindly repeat the download.
  • Communication is interrupted: after restoring the connection, first read the current values and confirm the device status and written scope before deciding whether to download again.
  • If no explicit success or failure result appears, do not assume that writing is complete; refresh and verify the values, and review the logs.

8.7 Motor Parameter Calibration Process#

This section describes the general process for adjusting motor parameters with the MCU Calibration module. The specific test speeds, parameter ranges, and acceptance criteria are governed by the calibration specification approved for the target project.

Prerequisites:

  • Position self-learning and rotation-direction verification have been completed.
  • A pre-calibration parameter backup has been saved and TRACE frame recording is ready. For the recording method, see Section 9, View and Export TRACE Frames.
  • The motor is in the safe load state specified by the project, and the cooling, power supply, emergency-stop, and high-voltage power-disconnection conditions are normal.
  • For a vehicle test, the mechanical braking system should be checked before testing to confirm that braking force reaches the design range and the brake-assist system operates normally.
  • The target speed, signals to observe, permitted range, and stop conditions for this test have been defined.

Procedure:

  1. Begin testing in the low-speed range specified by the project. For initial verification, a test point may be selected within the approved 200–500 RPM range.
  2. Use the TRACE window to record target speed, actual speed, current, fault status, and other signals required by the project.
  3. Check how the actual value follows the target value, and confirm that there is no sustained oscillation, significant overshoot, excessively slow response, abnormal current, abnormal noise, or abnormal temperature rise.
  4. After low-speed verification passes, increase the test speed step by step as specified by the project; you must not jump directly to high-speed testing.
  5. Analyze the response using the frame recording. In each round, prioritize the parameters with the greatest effect and limit the number of modified parameters to 1–2.
  6. After writing parameters, click Update parameter values, confirm that the actual values match the target values, and then repeat the same test condition.
  7. Compare tracking error, overshoot, oscillation, and response time before and after modification, and record the parameter changes and test results.
  8. Repeat the analysis, adjustment, and verification until every specified operating condition meets the project acceptance criteria.
  9. After completing calibration, clear the search criteria, select the parameter groups to deliver, update the parameter values, and save the final parameters as a TXT file.
  10. Stop control, set the torque and speed target values to zero, and disconnect high voltage before low voltage in accordance with the equipment safety standards.

Expected result: Each specified operating condition meets the project acceptance criteria, and the final parameters, TRACE frames, and modification records are saved completely.

Troubleshooting: If sustained oscillation, significant overshoot, a loss-of-control tendency, abnormal sound, vibration, current, temperature, or a fault occurs, immediately use the emergency stop or disconnect high voltage in accordance with the equipment standards. Before resuming the test, analyze the TRACE data and logs and check the parameters and test conditions. You must not continue increasing speed or modifying parameters repeatedly while the cause is unknown.

Calibration records:

  • Final TXT parameter file.
  • Parameter modification records, reasons for modification, and values before and after modification.
  • TRACE frame recordings from before and after modification.
  • Test conditions, including software version, power supply, load, and test speed.
  • Records of abnormal phenomena and their handling.
  • Final parameters requiring permanent integration and the corresponding software-generation or flashing records.

9. View and Export TRACE Frames#

9.1 Open TRACE#

Prerequisite: The CAN channel has been connected as needed.

Procedure: On the Status, Flashing, or an MCU-related page, click the TRACE button in the upper-right corner to open a separate window.

The TRACE list contains these commonly used columns:

  • Frame number
  • Time
  • Transmit/receive direction
  • CAN ID
  • Data length
  • Data content
  • Cumulative count for the same CAN ID
  • Signals decoded after a DBC is applied

Expected result: The TRACE window opens. When CAN is connected and frames are present on the bus, the list starts displaying data.

Troubleshooting: If no frame appears in the window, check the CAN connection, bit rate, bus wiring, and whether the target device is transmitting frames.

9.2 View Frames#

Procedure:

  1. Establish a CAN connection and open TRACE.
  2. Observe whether frames continue to appear in the list.
  3. To view a fixed position, click Pause List Scrolling. This button pauses only automatic scrolling; frame reception continues.
  4. Enable List Display to view the complete frame history. When it is disabled, only the latest frame for each CAN ID is retained for real-time observation.
  5. Enable Time Difference Display to view the time difference between two adjacent occurrences of the same CAN ID.
  6. Count indicates the cumulative number of occurrences for the same CAN ID.
  7. To begin observing again, first export any records that must be retained, and then click Clear the message buffer.

Expected result: TRACE displays CAN frames in the selected mode. New frames continue to be received and the count continues to update while scrolling is paused.

Troubleshooting:

  • It is normal for the count to keep increasing after scrolling is paused. Export the current record first if it must be retained.
  • Data cannot be recovered in the window after it is cleared. If it is cleared by mistake, it can only be collected again.
  • If the time difference is abnormal, first confirm that the same CAN ID is being observed, and check the bus load and transmission period.

9.3 Import a DBC#

Prerequisite: A .dbc or .xlsx file consistent with the current bus definition is ready.

Note: The XLSX file must use the specified row-and-column structure; otherwise, it may fail to load.

Procedure:

  1. Click Import DBC.
  2. Select a .dbc or .xlsx file.
  3. For combined decoding, additional files can be imported. Importing a maximum of three files at a time is recommended.
  4. Expand a frame row to view the decoded signals.
  5. To remove the decoding definitions, click Clear DBC.

Expected result: A frame matching the definition can be expanded to display its signals.

Troubleshooting:

  • If no decoded signal result is available, check whether the frame ID, extended-frame setting, byte order, and signal definition match the current bus.
  • If more than three files are imported in the current session, only the first three file paths are restored after the application restarts. For reliable reuse, keep the number at three or fewer.

9.4 Export a Recording#

Prerequisite: The frames to be saved have been collected in TRACE.

Procedure:

  1. Click Export the TRACE file.
  2. Select Vector or PCAN format.
  3. Select the save location and file name.
  4. Wait for the application to report that export is complete.

Expected result: A recording file in the selected format is created at the target location.

Troubleshooting: If export fails, confirm that the target directory is writable, the target file is not in use, and TRACE contains valid frames.

Before exporting, it is recommended to record the time of the fault, operation steps, bit rate, and controller status for subsequent analysis.

Prerequisite: A maximum of three input files in supported formats are ready, and the source and applicable project of each file have been confirmed before merging.

Excel input rules:

  • Frame and signal names must begin with an English letter.

13. Troubleshooting#

13.1 The Application Does Not Start#

  1. Confirm that the system is Windows 10/11 x64.
  2. Confirm that .NET 8 SDK x64 is installed.
  3. If .NET, Windows Desktop Runtime, or ASP.NET Core Runtime is still reported missing, run the SDK installer again and select repair or reinstallation.
  4. Restart Windows before running the application again.
  5. Press Win + R, enter %LOCALAPPDATA%\Programs\LeElectriX_FlashTool\logs, and collect the App logs from the corresponding time.
  6. If it still fails, provide the logs to technical support.

13.2 The CAN Adapter Is Not Detected#

  1. Unplug and reconnect USB.
  2. Check the adapter indicators and power supply.
  3. Check whether the manufacturer's driver is installed correctly.
  4. Close other software that may be using the CAN device.
  5. When using a ZLG adapter, if Device Manager recognizes the device but the application still cannot detect it, install the VC++ runtime as described in Section 2.4.
  6. Scan for devices again.

13.3 CAN Does Not Connect#

  1. Check the device, channel, and bit rate.
  2. Check the target-controller power supply and CAN wiring.
  3. Confirm that the bus termination resistance meets the system requirements.
  4. Disconnect and then reconnect.
  5. Review the error information in the CAN logs.

13.4 Bit-rate Scan Fails#

  • Confirm that periodic frames are actually present on the bus.
  • Confirm that CAN_H and CAN_L are not reversed.
  • Find the bit rate in the device documentation and select it manually.

13.5 License Loading Fails#

  • Loading is successful only when the success prompt appears, the license status is updated, and the authorized modules refresh.
  • Confirm that the file extension is .lic.
  • Confirm that the file came from the software provider and is not damaged.
  • Confirm that the license matches the current software and licensed target.
  • If no success prompt appears or the status does not change, also treat the operation as a loading failure and contact the software provider to verify validity.

13.6 HEX Loading or Flashing Fails#

  • Check the integrity of the HEX file and the target controller model.
  • Check the CAN connection, bit rate, and power supply.
  • Power may be cycled as described in Section 6.4 only if the log is still waiting to enter the Bootloader and erasing or transfer has not started.
  • After erasing or transfer has started, you must not cut power or disconnect the connection; retain the flashing and DoCAN logs and contact technical support.

13.7 The Parameter Definition File Does Not Load#

  • Confirm that the file is an .xls or .xlsx file.
  • Confirm that the file remains at the location from which it was imported.
  • Import it again from the Settings page.
  • Check the parameter-file version and format.

13.8 Parameter Read, Write, or Download Fails#

  • Check CAN communication and MCU handshake status.
  • Confirm that the controller is in an operating state that permits calibration.
  • The interface cannot guarantee automatic upper- and lower-limit validation for every parameter; before writing, check the unit and permitted range against the approved parameter definition.
  • Confirm that the TXT parameter-value file is consistent with the current parameter definition. For a complete download, first clear the search criteria and select all required parameter groups.
  • Batch writing starts automatically after file selection. A success prompt indicates only that the matching items in the current list have been written.
  • After a failure, first refresh all target parameters and review the logs; do not write repeatedly in succession.
